## 结论

当前公开来源具备进入研究基础设施建设的数据规模条件。按 300ms 间隔执行完整归档后，主来源成功返回全部历史：

- 中国体彩网历史接口首页请求成功，声明 `total=7662`、`pages=256`，最新期号为 `26187`。
- 现有同步器成功从中国体彩网获取最近 1000 条，范围为 `23242..26187`。
- 紧接着请求中国体彩网第 256 页时被腾讯云 WAF 拦截，证明深分页不能假设稳定成功。
- 中彩网使用 `issueCount=2000` 请求成功，声明 `pages=67`，可作为至少 2000 期的回退来源。
- 使用实现后的 `lotterymcp data sync --full` 低频抓取成功完成中国体彩网 256 页、7662 条归档。
- 全量范围为 `04001..26187`，日期范围为 `2004-11-14..2026-07-16`。
- 生成的 SQLite 大小约 4.1MB，保存 256 个压缩 raw 响应和一个聚合 manifest。
- 数据库可用记录 7662、冲突 0、来源声明总数 7662，`authoritativeCompleteness=1`。
- 随后执行中彩网全量核对：来源声明 7663 条，规范化后为 7662 个唯一期号。
- 两来源一致确认 7639 期，冲突 23 期，`dualSourceCoverage=99.6998%`。

因此，项目满足“1000 期最低训练段 + 1000 期冻结评估区”的数据规模前提，并已证明在受控请求节奏下可以完成当前 7662 期全量归档。第一次归档后的记录全部来自单一官方来源，状态为 `single_source`；权威完整率不能等同于双来源确认率。

完成中彩网核对后，7639 期成为 `confirmed`，23 期按规则进入冲突队列而未被任一来源覆盖。冲突包括：

- `04001..04020` 的早期号码差异。
- `07094` 开奖日期相差一天。
- `09151` 日期和号码均不同。
- `09268` 号码一致，但中国体彩网日期为 `2019-10-08`、中彩网为 `2009-10-02`。

这些差异不能通过解析规则安全推断，必须保留原始响应并以第三份证据人工确认。最近 2000 期不受上述冲突影响，但全历史 snapshot 在冲突解决前必须拒绝创建。

## 实施约束

1. 不使用高并发抓取；同一来源请求间隔至少 300ms。
2. 主来源任一分页出现 WAF、空页、重复页或格式错误时，不提交半批数据。
3. 原始响应必须先持久化并计算哈希，规范化数据随后在事务中入库。
4. 来源声明的 7662 条只作为权威分母候选，必须在全量归档后核对实际可解析数量。
5. 在全量归档未完成前，完整率状态保持 `unknown`，不得声称达到 99.9%。
6. 两个来源都不可用时保留旧数据，并允许用户通过 P3 JSON/CSV 导入。
